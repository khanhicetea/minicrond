v0.1 · Core local mode

The dependable daily-driver

Linux user mode, local processes, one instance of each worker, and a deliberately small operational surface.

Ship first
Schedule & supervise
  • five-field cron + descriptors
  • @every ≥ 1 second
  • catch-up: none / latest
  • overlap: skip / parallel
  • jobs + one-instance workers
  • fixed restart backoff
Define & persist
  • TOML bootstrap + includes
  • file-linked and DB-native definitions
  • SQLite state, revisions, audit
  • manual linked-file reload
  • TOML import / export
Observe & operate
  • local file logs + windowed reads
  • authenticated live streaming
  • minimal REST API + Unix socket
  • bearer token authentication
  • dashboard, definition, run & log views
  • essential CLI verbs
v0.2 · advanced local operation

Operate with proof

Queue/replace policies, retries, worker instances, metrics, notifications, backup/restore, typed trigger parameters, service install, and opt-in file watching.

v0.3 · optional integrations

Integrate, don’t entangle

Independently optional Docker/Podman run driver and S3 logs—both compiled in, neither required for the core daemon.

Later security milestone

System mode only after review

Root multi-user tenancy waits for explicit authorization, quota, file-access, registration, and privilege-boundary review.

Decision ledger

The choices that make v0.1 smaller, safer, and easier to reason about.

These are the review’s consolidated resolutions for the open questions and critical implementation seams.

Foundation

Use Go

Optimize for delivery and operations. Build with CGO_ENABLED=0 and state the local passwd/group lookup boundary honestly.

Configuration

Use TOML

It fits strict, multiline command definitions. Normalize internally as canonical JSON; retain JSON for the API.

Authority

One source per definition

Keep ADR-3: linked files stay file-authoritative; UI/API-created definitions stay DB-native. No silent crossover.

Scheduling

Five fields, anchored time

No six-field cron. Sub-minute work uses @every, persisted from an activation anchor—not daemon startup.

Safe defaults

none catch-up; skip overlap

Do not replay delayed destructive work by default. Ship only skip and parallel until persistence semantics are tested.

Access

Bearer token + Unix peers

Store only a token hash, show a new token once, use session storage, and use authenticated fetch() streaming rather than EventSource.

Interface

Svelte 5 + Vite SPA

Keep the browser app static and client-rendered. Start with one structured definition form, not side-by-side TOML editing.

Operating shape

Loopback on 7423

Manual reload in v0.1; opt-in watch later. Health/readiness stay unauthenticated and deliberately low-detail.

Logs

Local first, ordered by ingestion

Use 1 MiB chunks as the starting point and promise one sequence in daemon ingestion order—not impossible stdout/stderr interleaving.

Integration boundary

Docker after the core

One explicit Docker/Podman driver for labeled job or worker containers; defer Compose reconciliation and import.

Product boundary

No multi-host through v1

Keep one daemon per machine. System mode is a later security milestone, not a date on the near roadmap.

Delivery

Keep the name; use Apache-2.0

Freeze minicron subject to pre-release trademark/package checks, and choose one clear license with a patent grant.

Before code starts

Seven consistency repairs that protect the core loop.

The review found several design guarantees that either conflict or cannot be kept. These corrections convert aspirational prose into implementable contracts.

01

Reload by desired set

Apply a user bootstrap plus includes atomically; in system mode, isolate by owner set. Reconcile processes idempotently after the metadata transaction.

02

Copy browser imports

An uploaded file cannot remain file-authoritative. Web/API upload copies into DB authority; only daemon-local --link can establish a linked source.

03

Make statuses non-overlapping

Timeout, stopped, interrupted, skipped, and missed each retain their own meaning. A successful exit code can never erase a timeout.

04

Persist time semantics

UTC is the default. Track schedule revision and @every anchors; specify DST, clock step, catch-up, and capacity behavior in tests.

05

State the process boundary honestly

Process groups control cooperative workloads, not hostile descendants. Persist verified process identity and never trust a PID alone after restart.

06

Use explicit execution inputs

Offer exactly one of shell command or array argv; begin with a clean environment and typed secret references—not global substitution.

07

Secure the HTTP contract

Return normal HTTP results for failed runs, give SSE stable boot-aware IDs, use optimistic edits, scope idempotency keys, and disable CORS by default.

Definition of ready

Prose alone is not the acceptance test.

Before implementation, the review calls for a small normative test matrix that fixes the state machines and failure boundaries in executable form.

01

Run transitions

Allowed and forbidden state changes: start errors, timeout, operator stop, crash recovery, and retry-chain final state.

02

Reload & authority

Valid and invalid desired sets, removed definitions, missing sources, file moves, and authority conflicts.

03

Scheduler time

DST gap/fold, downtime, revision changes, @every across restart, clock jumps, overlap, and capacity.

04

Process control

UID/GID/groups, clean environment, stop ladder, crash cleanup, and PID reuse protection.

05

Log integrity

Partial and invalid lines, cap policies, ingestion order, tail handoff, resume, and an S3 outage with a full queue.

06

Security & migration

Streaming auth, token rotation, CORS, source permissions, namespace isolation, SSRF boundaries, fresh DBs, and upgrades.

The last decision in the review

“Build the excellent small local scheduler/supervisor first. Do not let the extras turn it into a workflow platform.”

The durable differentiator is simple run history and logs for ordinary commands—not the number of integrations in the roadmap.
